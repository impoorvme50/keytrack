# 水杉 Windows 与本地输入法的对照及优化建议

审查日期：2026-10-03。本文为只读审查与实施建议，未实施新的输入行为、替换词库、切换输入法或读取真实输入历史。

水杉参考为 `develop` 提交 [`2611e0f47045ec83095b1899f032fe39f4ec3a79`](https://github.com/metasequoiaime/msime-windows/tree/2611e0f47045ec83095b1899f032fe39f4ec3a79)，不是对某个已发布版本的 Windows 实机验收。伴随模型项目的测量文档固定为 `f4a3fc007fba051695ae8300de917bb824d458ba`。本地参考为 `ab6bda36bee06c4f9e922599abb2e404b118c41f`，Keytrack 0.4.4 / build 8、鼠须管 1.1.2。外部源码在临时目录阅读，没有运行其构建、安装、模型或测试。

值得借鉴的是候选质量评测、受约束的整句评分、后台结果身份校验，以及集中管理现有能力的设置。短期先完善已有功能和验收；专用模型和前端异步适配作为独立实验。

## 一、当前本地能力与实际状态

本地由鼠须管／雾凇提供基础输入，Keytrack 添加采集、控制台、常用语、接词实验、Kev 建议与释义。水杉是包含基础引擎、Windows TSF 前端、后台服务和设置程序的完整产品，因此功能清单不能直接等同于 Keytrack 的开发清单。

| 方面 | 水杉实现 | 本地已实现与真正缺口 |
| --- | --- | --- |
| 管理界面 | 集中的输入、外观、实用工具、词库、统计设置 | 已有 SwiftUI 原生控制台、字体搜索、拼音位置、备份／恢复；缺口是更多现有 Rime 能力的清晰入口 |
| 中英与实用输入 | 混输总开关、分项开关、英文触发长度；日期、Emoji 等 | 已部署 melt_eng、cn_en、Emoji、日期／农历、Unicode、金额、计算器等；不必重新造引擎 |
| 应用语言 | 按应用记忆或全局统一的运行状态 | 已有每应用默认中英文；仍要手填应用标识。默认规则与运行时记忆是不同能力 |
| 常用语 | 查询、新增、TSV 导入、UTF-8 导出 | 已有分类、搜索、多行编辑、重复表达发现和编码冲突检查；缺文件导入导出入口 |
| 候选释义 | 本地释义、用户 TSV 覆盖，以及可选后台网络补全 | 0.4.4 已有 EN／JA 120 词本地入门表；缺可扩充术语包、用户修订和纠错入口 |
| 普通候选学习 | 调频策略、选择后造词、固定位置和词条删除 | Rime 已有用户词典及删除候选能力；不要把手动常用语发现说成自动接词学习 |
| AI 建议 | 云生成候选，以及本地词格整句的专用模型评分 | Kev 主动触发、只选现有前 5 候选；中文收益未有足够独立评测，仍同步桥接 |
| 接词 | 与拼音整句解码不是同一功能 | 本地 librime-predict 按最后完整上屏文本精确查键，默认 3 项、最多一轮 |
| 统计与历史 | 默认关闭的本地字符计数和活跃时长 | Keytrack 为输入回看保留上屏原文；可增加暂停原文／仅统计等明确选择 |

当前只读状态检查通过：采集服务运行、Kev 开启且本机接口可用；接词实验已安装并开启，3 个候选、1 轮；释义关闭。首次默认关闭不代表用户当前关闭。

本机接词 DB 仍为 224 前键的 starter。9,998 前键／33,433 词对是已交付的公共候选资源，未替换本机默认库。精修在两份独立追加集的整体 Top 3 仅持平，不能宣称泛化质量提高。字体、最新公共库、释义、候选点击与四类应用的真实候选窗验收仍有未完成项；doctor 全绿不能替代体验验收。

本地证据：[README](../README.md)、[控制台](console.md)、[常用语发现](phrase-discovery.md)、[候选释义](candidate-glosses.md)、[公共库独立评测](public-prediction-evaluation-v3.md)、[异步能力核验](kev-async-feasibility.md)。

## 二、先做：验证日常收益，再改善使用入口

### 1. 补齐真实候选窗验收与三条独立质量基线

保留日常方案、当前库和现有开关，先对原方案与候选方案做可重复的比较。

| 基线 | 要回答的问题 | 建议记录 |
| --- | --- | --- |
| 拼音候选 | 原首选是否正确、目标是否在候选集合里 | 首选可接受率、前 5／更多候选的目标覆盖、前缀与完整答案区分 |
| Kev 五候选重排 | 主动请求是否比原顺序更好 | 救回、误提升、弃权、采用率、模型／进程桥接／可见菜单的分段延迟 |
| 提交后接词 | 完整上屏单位是否命中正确后词 | 全样例 Top 3、短语子集、无匹配、坏候选和默认库对照 |

现有 Kev 单元测试使用伪造概率、部分 native 测试使用固定桥接结果，只证明协议和按键行为。概率 ≥0.90、领先 ≥0.30 是当前策略，不等于中文正确率已经校准。评测应先冻结公开或原创的日常／工作样例，再运行；不能用接词的 Top 3 替代 Kev 重排评测，也不能边看题目边补答案。

水杉模型项目自己的[测量记录](https://github.com/metasequoiaime/chinese-ime-lm/blob/f4a3fc007fba051695ae8300de917bb824d458ba/docs/measurements.md)报告过精确词典命中被重排后退步，强调区分救回与弄坏、完整答案与前缀，以及目标根本不在候选集合的情况。其数据属于上游评测，不能转写成本机 Kev 结论。

真实验收覆盖编辑器、浏览器、终端、聊天应用：候选显示和点击、普通 Space／标点／退格／Escape、中英切换、Kev 触发与撤销、接词退出、长注释和焦点切换。使用公开测试文字，避免把引擎快照、设置预览当作真实菜单。

### 2. 集中管理现有输入工具

在原生控制台提供已有英文混输、Emoji、日期等功能的说明、示例和可支持的开关映射。先检查部署后方案实际配置，逐项映射，不把水杉的开关或固定插入位置直接写进雾凇。

水杉的[混输设置](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/ui-html/webview2/settings/ime-settings/src/modules/tools-settings.ts#L104-L158)将总开关和子项分开，关闭总开关仍保留子项，这是可借鉴的交互。我们的中文首选、现有排序与普通按键语义继续保留；英文触发长度是否能直接映射要先验证 Rime 能力。

应用语言页可先增加已安装应用选择器、友好名称和当前默认规则说明，减少手填 bundle ID。按应用默认语言已经实现；“运行时记忆／全局统一”需另验鼠须管能力，不能混作一个开关。

完成条件：重开仍保留设置，保存／恢复不覆盖其他配置；能力开关在实际候选窗生效，原中文和常用语输入不退步。

### 3. 扩充释义与常用语交换能力

释义优先做原创或许可明确的本地中英日术语包，覆盖样品、交期、报价、模具、质检等工作词；增加用户修订覆盖层。水杉的[自定义释义规则](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/engine/english/english_dictionary.cpp#L106-L119)是用户条目优先于标准库。现有本地 120 词不是待开发功能，新增的是覆盖与可维护性。

保留默认关闭、本地查询、完整候选匹配和 AI／联想标记优先；词表在初始化时载入，按键链不启动进程、读大文件或等网络。保存与恢复要包含个人覆盖层。多义词和专业译法需人工审校，不能把词量当成质量。

常用语可增加 JSON 导入导出以保留多行、分类，另支持 TSV。水杉[管理器](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/server/src/settings/dictionary_manager.cpp#L1270-L1421)有导入结果计数，但没有导入前预览；我们可以沿用现有草稿流程，先展示新增、相同内容、编码冲突和无效行，勾选后进入待保存列表，再保存并备份。这是改进建议，不是水杉已完成的能力。

## 三、独立实验：专用整句评分与安全异步

### 4. 先离线比较专用小模型

水杉先用词库词格与 kenlm 三元模型获得有限的整句候选，再用字符级 Transformer 评分。当前[评分接口](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/engine/neural/neural_decoder.h#L37-L48)默认对前 12 条路径重评分、前文预算为 64 个字符，实际上下文还受模型窗口与候选长度约束；未评分的尾部保留原序。静态与神经分数默认各占一半，模型不产生词格之外的句子。

[产品默认配置](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/installer/default_config/config.default.toml#L68-L85)开启词格、Google 本地解码器和速度档神经模型，效果档关闭；这里的 Google 解码器与 Google 网络云候选是两件事。[模型资源锁](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/neural-model/lock.json)固定两份文件为 4,486,280 与 25,480,184 字节。文件大小不是运行内存，也不是延迟证明。

本地实验可以比较 Rime 原序、Kev 主动选择、专用模型评分；先验证候选完整覆盖、分词／纠错后的真实编码、词典和用户词来源，不能按字数相同就判定回答了整个拼音。用户词、固定短语、前缀补全应分别评测。起步在隔离环境离线运行，记录内存、冷／热延迟和误提升；有收益后再讨论输入法接入。上游小样本模型名次不能证明它在本机中文任务上优于 Kev。

### 5. 安全异步需要前端支持

水杉[后台评分器](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/engine/neural/rescore_worker.cpp)限制待办、让新请求覆盖旧待办、在锁外评分、约束结果缓存并隔离后台异常。结果回到串行输入任务线程后才应用。这些工程原则值得借鉴。

线上请求以[会话和组合版本](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/engine/core/online_request_guard.h#L22-L27)及 TSF 激活周期拒绝过期结果；Server 保存[客户端和激活版本](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/server/src/ipc/async_request_origin.h#L10-L22)。取消后重输相同拼音已有[测试覆盖](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/engine/tests/src/test_online_input_session.cpp#L167-L180)。部分瞬时焦点变化会保留激活标识，跨输入框完整行为本轮未做实机验收。

本地当前通过 `os.execute` 启动同步桥接；2.5 秒是模型 HTTP 超时，包含进程启动的整个快捷键总耗时没有同等硬上限。已有[前端能力核验](kev-async-feasibility.md)未证明可靠输入框焦点版本和后台结果唤醒静止真实候选窗。Worker 写好文件、等下次按键或模拟按键都不能替代这两项关卡。

未来验收至少包括：会话／焦点／请求／候选版本、当前高亮和页面、开关、超时、取消、同拼音重输、离开再返回；所有过期结果只丢弃。打分和读写不能阻塞普通输入，且 Space／标点保持一次操作。前端关卡不满足时保留现有主动路径。

水杉也有需要改进的边界：[异步合并](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/server/src/ipc/event_listener_async_candidates.cpp#L28-L189)会在云／AI 结果到达时回首页、选首项，不能说它已解决所有高亮抢位。[绘制回执等待](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/server/src/ipc/event_listener_selection.cpp#L126-L164)有时间上限且超时继续当前页。我们应要求用户开始翻页、移动高亮或点选后冻结当前页，并按候选身份保留高亮；不直接搬其插入位置和等待数值。

## 四、随后完善的控制与维护

- **个人候选控制：** 先核验 Rime 原有用户词学习、删除候选和 ShadowCandidate 的学习行为，再考虑显式收藏、置顶、移除。不要另建一套无条件记录全部提交的学习库；自动跨提交接词学习继续沿用焦点关卡。
- **记录选择：** 增加临时暂停原文记录／仅统计／保留期限的明确入口，保留用户当前完整回看偏好。暂停必须作用于 Lua 采集器；只停 helper 仍会积累 JSONL。清理前展示范围，既有历史不自动删除。水杉[隐私说明](https://github.com/metasequoiaime/msime-windows/blob/2611e0f47045ec83095b1899f032fe39f4ec3a79/PRIVACY.md)明确区分统计内容、开关和保留期限，值得借鉴其表达。
- **完整状态页：** 现有 doctor 加上接词实际 DB 来源／版本、实验 snapshot 与日常方案漂移、释义脚本／词表／语言、最后部署状态。分别展示已安装、已开启和实际生效方案，不把服务运行当作用户正在用相应方案。

## 五、顺序、回退和采用边界

建议第一批只做基线与真实菜单验收、现有能力入口、释义术语包和常用语交换；专用模型先离线比较，异步前端另立范围。语音、手写、剪贴板和更多皮肤目前不优先。

每项独立保存、备份和回退。新设置读取旧状态，避免升级重置当前开关；词库保持 starter／公共候选／个人数据分离。替换 DB 前先确认来源和差异，在无活跃组合时切换并保留旧库。恢复原开关或旧库应能撤回增量，不覆盖后来独立编辑。

对照阶段的证据是源码、文档、已部署配置和只读状态核验，未测水杉 Windows 实际交互或加载其模型。随后按第一批范围完成本机 0.4.5 与本地 Kev 公开基线测量；交付、实测结果和仍未通过的候选窗验收见 [msime-round1.md](msime-round1.md)。水杉与本地的质量及速度优劣没有进行跨平台对照实验。
