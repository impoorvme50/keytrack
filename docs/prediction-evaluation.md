# 接词质量冻结评测

本评测把阶段 A/B 的数据质量判断固定为一个可重复的离线比较。它读取两列接词源文件和仓库内自造评测集，不读取个人输入历史、常用语、真实邮件或聊天记录，也不连接模型服务。

## 冻结集与独立性

`data/prediction/evaluation-v1.json` 共 **200 条**样例，涵盖日常沟通、饮食购物、出行交通、家庭家务、健康运动、工作会议、销售客户、产品采购、软件文档、学习休闲 **10 种情境**。每种情境有 20 条：8 条单词上屏、8 条短语上屏、2 条少见表达探针、2 条边界输入。

样例与可接受后词集合在首次评分之前独立编写并冻结，编写时没有查看 starter 的候选内容或新公共语料。未从语料抽取测试题，也未根据候选结果修改答案。样例是原创新造，许可为 MIT；此声明不改变待评测数据源自己的许可。

| 分类 | 数量 | 含义 |
| --- | --- | --- |
| `word` | 80 | 一个自然词作为完整上屏单位，例如“地铁” |
| `phrase` | 80 | 一次提交的完整短语，例如“我要去”；不退回查询“去” |
| `unmatched` | 20 | 少见的自造产品名、活动名或文档名，保留合理的可接受后词；是否命中由数据决定 |
| `boundary` | 20 | 标点、英文、数字或混合直输的完整单位，不期望产生接词，接受集为空 |

`unmatched` 是固定的未匹配探针组，并非根据某次评分临时挑出的漏词。以后词库实际收录这些完整键时可以得分，不会强行屏蔽其命中。报告同时列出每组的实际命中数。

冻结 SHA-256 为 `517b33578b18546c4136432f7a2065b3e81df4f7abbff597a92edaf4338e4048`，保存在 `data/prediction/evaluation-v1.manifest.json`。评分前核对哈希、200 条数量、至少 10 种情境、唯一样例 ID、四类数量和接受集约束；测试另外固定该版本的哈希。已有版本不随词库变化改题或改答案，新增评测题应另立版本，保留本版本报告。

这是小规模、均衡分组的合成集，不是个人实际输入的分布，也不代表所有中文接词质量。边界输入的负例不会被计为 Top 1/Top 3 命中；因此本集整体可接受率的理论上限是 180/200=90%。不出候选的边界成功单独统计。

## 查键与分母

评分直接调用 `scripts/build-predict-db.py` 的 `preprocess`，保持真实数据构建规则：两列输入、显式词对或 Unicode 前缀切分、重复词对取最大权重、同权重保留源顺序、默认每键保留最多 8 项、忽略后词为 `$` 的终止记录。这里不重新实现排序规则，也不把人工排序权重视为出现次数。

按最后一次完整上屏文本精确查询。没有运行时分词、尾词回溯、去空白、拼写修正或归一化。Top 3 只检查返回候选的前 3 项，后面的正确答案仍是 Top 3 不通过。

| 指标 | 分子 | 分母 |
| --- | --- | --- |
| 查键命中率 | 完整键返回至少一项的样例数 | 全部 200 条 |
| 整体 Top 1 可接受率 | 第 1 项在该样例接受集中的条数 | 全部 200 条 |
| 整体 Top 3 可接受率 | 前 3 项至少一项在接受集中的条数 | 全部 200 条 |
| 命中内 Top 3 可接受率 | 同上 | 实际返回至少一项的样例数 |
| 边界不出候选率 | 边界组中没有匹配结果的条数 | 边界 20 条 |

各类别与各情境使用各自分母，并同时输出计数和百分比。命中内没有样例时是 `0/0`、百分比为 `null`，Markdown 显示“不适用”，不会写成 0% 或 100%。机器报告保留每条完整键、接受集、保留候选与首次可接受排名，便于检查分母和具体失误。

## 复现与门槛

只建立 starter 基线，无下载、编译或输入法部署：

```sh
python3 scripts/evaluate-prediction.py \
  --json data/prediction/evaluation-starter-v1.report.json \
  --markdown data/prediction/evaluation-starter-v1.report.md
```

比较一个独立生成的新两列词库：

```sh
python3 scripts/evaluate-prediction.py \
  --candidate /absolute/path/public.ngram.tsv \
  --json /absolute/path/evaluation.json \
  --markdown /absolute/path/evaluation.md \
  --fail-on-gate
```

基线默认使用 starter。`--baseline`、`--candidate` 都能重复指定多个源，顺序就是 builder 的源顺序。`--max-candidates` 默认 8；其作用是数据保留上限，评分显示上限始终为 3。自定义评测集必须提供同名 `.manifest.json`，并满足 200 条与至少 10 情境的校验。

数据替换门槛同时要求：

1. 查键命中率相对 starter **至少提高 10 个百分点**；200 条中就是至少多命中 20 条。
2. **整体** Top 3 可接受率不下降，不能以命中样例内的比率替代。

判定使用整数计数，百分比四舍五入不会影响临界值。`--fail-on-gate` 在门槛未通过时退出码为 2；仍保存完整报告，便于解释失败。没有提供候选源时只生成基线，不做替换判断。报告无生成时间戳，在输入、builder 与参数不变时可逐字节复现，并记录源文件、预处理表与 builder 的 SHA-256。输出路径不能覆盖评测集、冻结清单或输入源。

即使两项数据门槛通过，仍需已有 native 精确 fixture、普通拼音和边界按键行为、性能与真实候选窗验证。此工具只评分离线候选表，不宣称已安装或已通过真实菜单行为；运行时关闭、取消与标点处理也不由本工具模拟。
