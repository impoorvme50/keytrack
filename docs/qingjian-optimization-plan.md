# Keytrack 优化方案：接词质量、异步建议与个人偏好

日期：2026-10-02。实施进度更新：2026-10-03。首批 A/B 代码与数据已交付，B 的真实候选窗验收仍待完成；其余阶段保留为后续范围。

本轮交付：200 条冻结评测、公开语料生成工具与 10,060 前键／35,222 词对候选库、2,000 次隔离引擎计时、原生字体搜索与拼音显示位置。原生保存／恢复已实际验证，9 个受影响文件恢复后哈希与测试前一致。桌面自动化未能切入鼠须管中文输入，真实候选窗、点击和四类应用验收尚未完成；新库未晋升默认，原有开关与默认库保留。

117 项 Python 回归及原生、引擎、打包组件检查通过。本机 Keytrack 已更新到 0.4.2，安装包和校验文件位于 `dist/`；应用备份与回退见外观记录。

当前鼠须管的可靠焦点边界与静止候选窗刷新两项关卡未满足，阶段 C 和自动跨提交学习未启用。阶段 D 的手动统计／常用语发现与阶段 E 译词本轮未实现。详细证据见 [公共库交付记录](public-prediction-data.md)、[外观记录](console.md#字体搜索与拼音显示补充2026-10-03) 和 [异步核验](kev-async-feasibility.md)。

本地基线为 `22e2c84`；青简参考版本固定为 [`c08ae57cb88b6a4a46f4a5e9c1d6d11c5e69222e`](https://github.com/qingjian-team/qingjian/tree/c08ae57cb88b6a4a46f4a5e9c1d6d11c5e69222e)。方案沿用鼠须管、雾凇拼音、librime-predict 和 SwiftUI 控制台，优先提高日常输入收益，再增加实验功能。

## 1. 建议顺序与交付范围

建议先扩充公共接词库，并同步补上字体选择；随后完成 Kev 异步接入验证。个人学习采用独立统计、批量应用，候选译词放在后续可选实验中。

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：建立基线 | 固定输入样例、计时边界；验证鼠须管焦点事件和候选刷新能力 | 数据质量有可重复的比较方法，异步接入的可行性有实际证据 |
| B：先改善日常体验 | 扩充公共接词库；增加字体搜索、拼音显示位置 | 覆盖提高，正常输入与退出不退步；真实候选窗确认字体与布局 |
| C：Kev 异步建议 | 普通拼音与接词使用独立请求类型；用户主动触发、可取消和撤销 | 不阻塞按键，过期结果不改菜单，静止候选窗也能收到有效结果 |
| D：个人偏好 | 默认关闭的个人二元学习；手动更新接词库；重复表达审核导入 | 个人数据单独管理，更新和回退可靠，重复安装保留数据 |
| E：可选译词 | 本地英文或日文短释义，独立开关 | 注释不挤占原标记，不改候选文字、顺序和上屏规则 |

A 的焦点/刷新验证与 B 的数据、外观工作可并行。若前端能力不足，B 仍可独立交付；C 和自动跨提交学习保持未启用。每阶段单独提交、验证和回退，不把全部功能合并成一次安装。

### 方案编写时的能力与主要缺口

- 已有公共接词库包含 224 个前词、896 条人工整理词对；已验证默认 3 项、一轮上限、数字/Tab 选择、空格退出、继续字母和 Escape。[数据说明](prediction-data.md)
- 当前 Kev 热键仍通过 `os.execute` 同步调用一次性桥接，模型请求超时为 2.5 秒。仓库没有持久异步 worker；[prediction 协议](prediction-kev-interface.md)目前是设计，尚无焦点版本计数和异步刷新实现。
- 外观已有 9 套浅/深配色、字号、横竖排列和间距；字体选择与拼音显示位置尚未接入。[控制台说明](console.md)
- 最近一轮记录为 89 项 Python 回归通过；引擎与真实候选窗分别有验收记录。这些是已有交付记录，实施时重新建立基线，不当作新增功能已通过。

## 2. 所有阶段共同遵守的输入规则

### 处理链与开关

采集器始终第一，Kev 热键处理器第二；接词 guard/predictor 按既有方案放在 `key_binder` 前。核对部署后的实际顺序，不能直接使用上游 `@before 0` 抢占采集器位置。

保留用户当前的本地联想、Kev、模型服务和外观状态。升级不重置已有开关；新增的异步路径、个人学习、候选译词首次默认关闭。联想候选仍默认 3 项、最多一轮。

| 操作 | 普通拼音状态 | 联想状态 |
| --- | --- | --- |
| 字母 | 按原规则输入拼音 | 退出联想，开始新的拼音 |
| 空格 | 按原规则提交当前候选 | 退出联想并传给应用；连续空格不选择接词 |
| 数字、Tab、点击 | 保留原方案规则 | 明确选择接词，选择后不继续第二轮 |
| Escape | 保留原方案规则 | 退出，不提交接词 |
| 退格 | 正常编辑 | 第一次仅退出联想，下一次正常删除 |
| 标点、中英切换 | 保留原规则 | 结束联想后正常输入或切换 |
| Kev 快捷键 | 主动请求；再次取消或撤销 | 主动请求接词建议；同样可取消或撤销 |

排序、释义和学习不自动提交文字，也不改变这些按键规则。常用语、历史、其他插件与日常雾凇方案继续保留。

### 数据与界面边界

原生设置继续使用 SwiftUI 和私有 stdin/stdout JSON 管道。新增后台组件不在控制台的串行设置队列里等待模型，不新增 HTTP 监听服务或模型服务。

历史数据库保持记录、查询、统计用途。个人学习只处理开启之后的新事件；常用语历史分析只在用户主动点击时只读执行。个人内容不进入公共词库、仓库、安装包或远程服务。

## 3. 阶段 A、B：公共接词库与外观

### 公共库生成

首版规模目标为 5,000–10,000 个前键、20,000–50,000 条词对，每个前键最多保留 8 项；显示数量仍由独立设置控制。最终规模由覆盖、质量、包体与延迟决定，不以记录数量作为成功标准。

优先从第一方 [LCCC 数据源](https://huggingface.co/datasets/thu-coai/lccc)独立抽样生成；其数据卡标注 MIT，内容为中文社交对话。固定实际下载文件、版本、哈希、抽样种子和许可文本，使用本项目解析器处理原始文件。词表与分词工具也分别记录来源和许可。

生成流程：固定来源 → 清洗 → 离线分词 → 提取词对与完整短语键 → 汇总计数 → 筛选与稳定排序 → 现有 DB builder → 清单和隔离测试。发布只包含必要词对和来源说明，不附原始对话。

关键规则：

1. librime-predict 按最后一次**完整上屏文本**精确查键，保持这条契约。仅有 `去 → 北京` 时，提交 `我想去` 不会自动命中。[上游行为](prediction-data.md#上游读取结果)
2. 在离线阶段补齐有长度上限、以词边界结束的连续短语键，例如从“我 想 去 北京”得到 `我想去 → 北京`。首版最多合并 3 个前词、12 个汉字；不在按键链上增加分词或尾词回溯。
3. 标点、英文、数字、对话轮次和未知词边界不跨越。过滤空串、控制字符、异常重复、链接、联系方式和明显不适合作为候选的内容，并做固定抽样检查。
4. starter 的 `100/90/80/70` 是人工顺序，不是出现次数。语料先独立汇总、按前键归一化；人工补充另列来源和策略，不能把两类权重直接相加。
5. 现有 builder 对重复词对取最大值；统计合并必须在它之前完成，每对只交一条最终记录。同分使用固定规则排序，确保重复生成可复现。
6. starter、fixture、新公共库分别保留；fixture 不随语料扩充变化。新库通过质量门槛后才作为默认公共资源。

### 评测与替换门槛

建立 200 条独立编写的日常、工作输入样例，覆盖至少 10 类情境。每条包含真实的完整上屏单位与可接受后词集合；分开报告单词上屏、短语上屏、无匹配和边界输入。

报告查键命中率、所有样例的 Top 1/Top 3 可接受率，以及命中样例内的 Top 3 可接受率，写明分母。旧空格接受记录不直接充当正确答案。初始替换门槛为：相对 starter，命中率提高至少 10 个百分点，整体 Top 3 可接受率不下降；已有精确 fixture 和正常输入检查全部通过。达不到时调整数据，保留原库。

### 外观补充

原生页面增加可搜索的字体列表，列表和候选预览使用实际字体；提供系统默认、未安装字体回退。候选字体先独立设置，编号和注释默认跟随，避免增加过多控制项。

增加“拼音显示：行内／候选窗”。本机鼠须管默认配置已包含 `font_face` 和 `inline_preedit`；实现时还要验证所选主题的覆盖优先级。设置只写受管块，保存前预览，保存后部署；恢复操作同时还原这两项原值。终端、TextEdit、浏览器和日常应用分别验证，预览不等同于真实候选窗。

## 4. 阶段 C：Kev 异步建议

### 必须先证明两项前端能力

- 能识别应用、窗口、输入框及输入会话的激活/失活；切换时使旧请求失效。前台应用采样、控制台焦点和候选文字相同都不足以证明会话相同。
- 后台结果到达后，能够安全唤醒输入线程，在用户不再按键时更新当前真实候选窗。不能靠模拟按键或等用户下一次输入来完成刷新。

先在隔离环境验证现有 Rime/鼠须管可用通知和适配接口。若必须修改鼠须管前端二进制，另行明确维护与安装成本；普通安装流程不直接替换用户输入法。两项能力任何一项未证明，就不启用自动应用异步结果。

### 请求和结果处理

沿用 [prediction 接口设计](prediction-kev-interface.md)，保留旧非空拼音校验，新增独立 `prediction` 类型。实现时给旧拼音请求兼容适配层，两种请求共用生命周期控制，不能伪造拼音。

热键处理只快照候选、发布有界请求并立即返回。内置 worker 验证请求并访问既有 Kev 服务；它不操作 Rime，前端适配层负责在输入线程应用结果。先证明非阻塞 IPC/队列机制，再验证耗时和故障；有限延迟测试不能证明普通文件写严格非阻塞。若另设临时持久队列，采用私有目录、随机文件名、原子发布、大小上限和及时清理，磁盘写入移到按键链之外。

结果同时核对请求 ID、会话/焦点/输入/联想版本计数、方案、候选 fingerprint、开关、菜单、高亮和超时。继续输入、编辑、翻页、移动选择、提交、退出、中英切换、换输入框、关闭后重开都使旧结果失效，即使后来回到相同文字也不能复用旧请求。

每个会话最多一个待处理请求；再次快捷键取消等待，或撤销同一候选快照的已应用建议。无服务、超时、worker 异常或未就绪时保留本地候选，普通输入立即可用。前文只取当前会话，最多 160 字、60 秒，焦点或编辑变化时清空。

### 第一版建议语义

现有 Kev 给出建议项和置信度，首版继续沿用概率至少 0.90、领先至少 0.30 才提升首位的规则；其余候选保持原有相对顺序。低把握只标记，不改顺序。

实施时补充成功响应的 `suggestion_id` 与 `adopt`：建议 ID 必须属于候选快照；低把握时 `adopt=false`、`order` 保留原顺序，但仍能明确标记建议项。仅有 `order` 无法表达这种状态。桥接/worker 将现有 index/adopt 转成完整稳定排列；输入线程核对响应并应用，SwiftUI 设置端不操作 Rime 菜单。这不表示模型已经具备全候选精细排序能力；完整评分排序作为后续扩展，另做质量评测。

实验方案的 `prediction_filter` 当前排最后，并重写联想注释。需统一组合规则，保留已有注释和 AI 标记，例如 `联想 · ✦ AI · 数字/Tab`；不能只扩桥接而让最后的过滤器抹掉标记。验证 Emoji/OpenCC 包装、候选类型及部署顺序；撤销恢复同一快照的原顺序与注释。

## 5. 阶段 D：个人学习与常用语发现

### 推荐首版：后台统计，手动应用

新增独立的个人接词学习开关，首次关闭。只处理启用后的有效新词对，按完整上屏单位记录；标点、英文、超时、方案和输入框变化断链。自动跨提交学习同样依赖阶段 A 的可靠会话边界。

个人文件放在 `~/.keytrack/prediction/personal/`：聚合计数、版本清单、有界暂存事件和生成结果分别管理。该路径只是拟定设计，当前尚未创建。

Rime 回调不查 SQLite、不分词、不构建 DB、不等待 worker。既有采集器独占其日志的吸收流程，个人 worker 不能抢读或搬走 `ime_commits.jsonl`。新事件通过独立、有界通道发布；使用事件 ID 防止崩溃重放重复计数，关闭时拒绝旧状态版本的事件。队列满或后台故障允许丢弃学习事件，并显示丢弃计数，输入和历史采集继续正常。

普通 Lua 文件追加仍是同步磁盘 I/O；`pcall` 不能把它变成非阻塞。若选择该方式，必须测额外延迟和故障边界；需要严格无磁盘等待时，先实现非阻塞队列支持。

首版仅用二元计数：词对至少出现 3 次、来自至少 2 个有效会话后才进入个人候选；个人影响设上限，不让一次误选压倒公共候选。记录候选来源和是否明确选择，避免自动路径自我强化；具体权重依据自造数据和冻结评测确定。

AI 排序撤销不产生学习记录。联想状态第一次退格只退出菜单，没有删除文字，不能据此退回学习计数。仅在能确认提交撤销/重选关系时回退对应增量；无法确认的编辑断链，提供词级“忘记”入口。

### 词库应用与安装迁移

点击“更新个人接词”后：后台生成公共+个人合并库 → 校验 → 展示变更数量 → 确认无活跃组合或联想菜单 → 取消并使待处理 AI 请求和会话版本失效 → 备份/原子替换 → 请求部署并验证新会话版本。忙时延后，不能因联想片段长度为零就认定输入会话空闲。不是每次学习都重部署。

现有 predict DB 是只读映射，替换磁盘文件不保证当前会话读到新库。应用批次必须确认旧映射刷新；失败保留上一已验证版本。界面显示“统计已更新／上次应用版本”，不宣称刚学到的词即时生效。

现有 builder 是维护者工具，依赖编译器、Boost 和匹配的 librime 头文件。一键更新必须先交付随包可运行的已验证 builder，或独立可移植写库组件；普通用户不额外安装开发工具。未完成这个关卡时，只交付统计与导出，不开放一键应用。

安装清单从 `custom_db` 布尔值迁移为明确的 `public / custom / merged` 模式，并记录公共版本、个人版本、激活版本、上一可用版本、生成参数和引擎兼容信息。旧清单保守迁移；重复安装不覆盖个人聚合库、自定义库或已激活合并库。公共升级提示可重新生成合并库，不悄悄冻结在旧公共库，也不自动替换用户偏好。

`custom` 模式下先展示合并基底和替换影响，保留原自定义版本；不能在“更新个人接词”时默默换回公共库。首版若未支持自定义库合并，则保留统计/导出，禁止该模式的一键覆盖。

关闭“个人学习”只停止新计数；“停用个人偏好”切回公共库，需完成一次安全刷新。清空个人数据是单独操作，说明影响并提供备份；不清历史和常用语，清空后还需刷新掉旧合并库。

### 常用语发现

在原生常用语页增加“发现重复表达”。用户选择“分析已有历史”时，仅本地只读扫描；或使用开启之后的独立重复表达统计。该分析不作为个人接词训练的隐式入口。

展示完整表达、频次、建议短编码、内容重复和编码冲突，用户勾选后走现有保存、备份和应用流程。默认分析最近 30 天，另可选择范围；初始建议至少 3 次、跨 2 个会话，自动测试使用自造数据。过滤碎片和低价值短词，号码、地址等不自动导入；保留拒绝记录，避免同一建议反复出现。

## 6. 阶段 E：候选本地译词

新增默认关闭的“候选释义”，一次选择英语或日语。第一版只查询本地短词表，未命中留空；不自动联网补词，不让 Kev 承担文字生成。

通过鼠须管 comment 显示一条短译词，可选词性/日语假名；初始长度上限 24 个字符，超长截断。现有「联想」「✦ AI」和选择提示优先保留，过宽时先省略译词。统一注释组合函数由最终过滤器使用，避免各插件互相覆盖。

词表独立记录来源、许可和校对情况；个人释义单独存放。第一版不引入“掌握词汇量”指标；曝光次数不能等同于掌握程度。验证无释义、有 AI、有联想及常用语时的注释，不改变原候选排序、文字和按键行为。

## 7. 验收门槛与性能预算

以下指标是拟定目标，不是新功能实测结果。实施时固定设备、引擎版本、库版本、冷热状态、测量边界和样本数；不把不同数据集的耗时相减。

| 项目 | 已有记录 | 新阶段验收方式与初始目标 |
| --- | --- | --- |
| 引擎提交与菜单计算 | fixture 热状态 11 次：中位约 0.24 ms，最大约 0.37 ms；含观察器和提交，不是纯 DB 时间 | 新库每组至少 1,000 次热测，目标 p95 ≤ 5 ms、p99 ≤ 10 ms；冷启动与换库另列 |
| 真实候选窗更新 | starter 11 次：中位 34.15 ms，最大 43.20 ms；测到 WindowServer 可见布局，非逐像素完成 | 相同边界至少 100 次，目标 p95 ≤ 60 ms；分别报告失败次数与冷热状态 |
| Kev 热键返回 | 现有路径会同步等待模型 | 异步路径热状态 p95 ≤ 5 ms；worker 故障不把模型等待带进按键链 |
| 个人学习额外成本 | 尚无实现 | 开/关对照，热状态按键额外 p95 ≤ 1 ms；单测写入、首次加载、队列满和故障 |
| 接词质量 | starter 无独立留出集评分 | 200 条冻结样例，命中提升 ≥ 10 个百分点，整体 Top 3 可接受率不降 |

现有耗时依据 [实验验收记录](prediction-experiment.md#验证记录2026-10-02)，不代表本轮重新测量。模型推理、队列等待、热键返回、结果校验和界面更新分别计时；本地联想与译词不等待模型。预算未达标时先缩小库/快照、修复发布路径或保持功能未启用。

### 必做检查

- 隔离 HOME + fixture：已知候选精确匹配，无匹配正常继续；普通拼音、标点、中英切换、常用语、Escape、退格和连续空格全部正常。
- 采集：实际部署顺序正确；已知按键序列精确计数，新增分钟桶保留有效采集版本，释放事件不重复计算。
- 异步：延迟、乱序、重复响应；输入后回到同文本；换应用/窗口/输入框；移动选中后返回；关闭后重开；取消、撤销、worker 崩溃。旧结果均不得重开或改写菜单。
- 注释：联想、AI、译词独立及组合状态；Emoji/OpenCC 后仍可识别；撤销恢复原注释。
- 学习：会话断链、重复事件去重、关闭后不新增、错误数据不覆盖旧库、磁盘写失败正常输入、批次应用与版本验证。
- 安装：备份、幂等、插件占位冲突拒绝、公共升级、自定义库/合并库保留、旧设置迁移、回退再安装。
- 真实窗口：TextEdit、浏览器、终端和至少一个日常应用；静止刷新与跨输入框失效分别验证。候选点击提交补做，不能用数字/Tab 通过代替点击通过。

Python 回归以原始 89 项记录为起点，本轮增加行为测试后共 117 项通过。只在改动、失败或未解决问题需要时扩展测试。修改本机 Rime 前读取其 AGENTS.md、备份受影响配置；修改后执行要求的 lint，词典源改动再执行对应构建检查。引擎、包运行组件和真实候选窗分别记录结果。
