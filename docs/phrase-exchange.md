# 常用语文件导入与导出

常用语文件先做本地预览。只有标记为“可新增”的条目可以加入待保存草稿；文件里的相同内容、编码冲突和无效项不会覆盖已有表达。加入草稿后，仍通过现有“保存并应用”流程校验、备份并生效。

原文里的首尾空白、内部空格、制表符、双引号和多行内容都保留。分类沿用现有保存规则：去除分类名称首尾空白，不修改内部文字。内容相同但分类不同的条目也视为重复，不自动更新已有分类。

## 文件格式

建议使用 UTF-8 JSON，版本固定为 `schema_version: 1`：

```json
{
  "schema_version": 1,
  "phrases": [
    {
      "code": "qreply",
      "text": "第一行\n第二行\t保留制表符",
      "category": "客户回复"
    }
  ]
}
```

`category` 省略时使用“常用”。JSON 不接受重复字段或 NaN／Infinity 数值，容器嵌套最多 16 层，不读取路径、不执行脚本。格式版本、列表结构或 JSON 语法错误会拒绝整个文件；单条编码、内容和分类的错误在预览中显示为无效项。

TSV 使用标准制表符分隔的 CSV 规则。第一条记录必须是 `code`、`text`、`category` 三列同序标题；导入也接受只有 `code`、`text` 的同序标题，此时分类使用“常用”。导出始终包含三列。

字段包含双引号、制表符或换行时使用双引号包裹，字段内双引号写作两个双引号。多行内容是同一条记录，不能直接按文件行数拆分。例如：

```text
code	text	category
qreply	"第一行
第二行说：""收到"""	客户回复
```

这里的列间距表示真正的制表符。支持 UTF-8 BOM 和 LF／CRLF 记录分隔符；不会改变带引号的表达内部换行。列数不一致和空记录会显示为无效项，不静默丢弃多余列。缺少标题或引号未闭合等语法错误会拒绝整个文件。

## 预览规则与边界

| 状态 | 判断 | 可加入草稿 |
|---|---|---|
| `new` | 通过现有保存校验，没有相同内容或编码冲突 | 是 |
| `duplicate` | 草稿已有完全相同内容，或文件中前面的可新增条目已有相同内容 | 否 |
| `conflict` | 编码已被草稿的其他内容使用，或文件中同一编码对应不同内容 | 否 |
| `invalid` | 编码、文字、分类或 TSV 列数不符合规则 | 否 |

相同内容按原文精确比较，不去空白、不合并换行。文件里同一编码对应不同内容时，这一编码的所有竞争条目都标记冲突，不任意选择第一条。同编码、同内容但分类不同，只保留第一条可新增条目。无效项不会占用编码，也不会阻止后面的合格条目。

每次导入或导出文本最多 **2,000,000 UTF-8 字节**。预览最多 **600 条记录**，方便选择其中部分；最终草稿与保存仍最多 **300 条**，导出也沿用 300 条保存上限。300 条、每条 2000 个中文字符的正常组合可完整导出再导入；极端大量 emoji 等组合若超出字节预算，会明确拒绝导出，不生成无法再导入的文件。短编码、特殊前缀和字段长度规则直接复用 `console.validate_phrases`，没有另建一套保存规则。

模块只处理调用方提供的文件文字和当前草稿，不读取历史输入、不写文件、不自动保存，也不改变任何输入开关。文件选择、预览选择、加入草稿与最终保存由原生控制台负责。

## 后端接口

```python
preview(content: str, format: str, existing: list[dict]) -> dict
export_phrases(items: list[dict], format: str = "json") -> str
```

`format` 只接受小写 `json` 或 `tsv`。`existing` 应传入当前草稿，包括未保存修改；调用方仍须保留原有保存版本校验。函数不会原地修改参数。

`preview` 返回：

```json
{
  "rows": [
    {
      "id": "稳定的64字符SHA256标识",
      "code": "qreply",
      "text": "原始表达",
      "category": "客户回复",
      "status": "new",
      "message": "可加入待保存草稿"
    }
  ],
  "counts": {"total": 1, "new": 1, "duplicate": 0, "conflict": 0, "invalid": 0}
}
```

每条 `id` 根据完整文件文字和记录序号计算；同一文件预览稳定，重复记录标识不同。返回字段都是字符串，无法表示为有效 UTF-8 的错误字段以空字符串显示并标记无效。格式、结构、预算或现有草稿无效时抛出 `ValueError`；无效文件不会留下半份预览。

`export_phrases` 返回带结尾换行的完整 JSON 或 TSV 字符串；无效草稿或预算超限抛出 `ValueError`，写入目标文件由调用方处理。

验证覆盖 JSON／TSV 原文往返、标准 CSV 兼容、同内容／同编码冲突、无效行隔离、BOM／多行、畸形与重复字段、恶意内容只作数据、Unicode 错误以及字节／记录／保存预算。测试使用合成表达，不接触真实输入历史。
