# keytrack 需求文档

> 整理自 2026-07-28 讨论与试跑反馈。  
> 目标：做一款**给自己用的本地输入回看工具**——不只统计哪个键按得最多，而是能直观看到「今天输入了什么」。

---

## 1. 背景与动机

现有键盘追踪 / 键盘记录产品大多只做：

- 按键频率（哪个键按得最多）
- 鼠标移动距离、按键总数等数字看板

这类数据对日常回顾意义有限。更有价值的是：

- 能按时间回看**今天实际输入了什么内容**
- 知道内容发生在**哪个应用**里
- 同时保留操作层指标（速度、频率、节奏）作为辅助

开源里「只统计、不记内容」的产品（如 ActivityWatch、WhatPulse）较成熟；「记完整内容」的多为恶意/教学向 keylogger，产品形态与伦理定位不符。**本地、自用、内容回看**这一档基本空白，因此自建。

---

## 2. 产品目标

### 2.1 核心目标

用户能在本机打开回看界面（当前为终端，后续可扩展网页看板），看到：

1. **今天（或指定某天）输入了什么**——可读文本，按时间线排列  
2. **每段输入发生在哪个应用**  
3. **操作层摘要**——按键频率 Top、打字速度 / 节奏（活跃分钟、平均 / 峰值、按小时分布）

### 2.2 非目标（当前不做）

- 不上云、不向任何服务器上传输入内容  
- 不做针对他人机器的隐蔽监控 / 远控  
- 不替代剪贴板历史、全文搜索型「生活录屏」（如 Rewind）的完整能力  
- 第一版不以商业分发、跨平台完整支持为硬性目标（先做好 macOS 自用）

---

## 3. 用户与使用场景

| 角色 | 场景 |
|------|------|
| 本人（本机唯一使用者） | 下班前回顾「今天在微信 / 邮件 / IDE 里写了什么」 |
| 本人 | 想知道今天打字有多勤、峰值在哪个时段、哪些键最常按 |
| 本人 | 中文为主办公：回看内容必须是**最终上屏汉字**，不能只是拼音字母 |

约束：数据含敏感信息风险（密码、私信等），产品必须默认本地、可后续加强过滤。

---

## 4. 功能需求

### 4.1 内容记录（P0）

| ID | 需求 | 说明 |
|----|------|------|
| C-1 | 记录可读输入内容 | 不只是键码统计，要能重建 / 还原「打了什么」 |
| C-2 | 中文必须是上屏结果 | 用拼音输入时，回看应为汉字（如「我知道」），而非 `wozhidao` |
| C-3 | 按时间分段 | 连续输入组成片段；停顿或切换上下文时切段落库 |
| C-4 | 标注应用 | 每段标明前台应用名（如 Cursor、微信、Safari） |
| C-5 | 按天回看 | 支持 `今天` / `昨天` / 指定日期 |
| C-6 | 全应用覆盖 | **希望所有常用应用都能记到内容**，含 Electron（如 Cursor）、IM、浏览器、原生 App |

### 4.2 操作指标（P0，与内容并列）

| ID | 需求 | 说明 |
|----|------|------|
| M-1 | 按键频率 | 按天 Top N（哪个键按得最多），含 space / backspace 等 |
| M-2 | 输入节奏 / 速度 | 活跃分钟、击/分钟、粗略 WPM 或更贴合中文的「字/分钟」 |
| M-3 | 时段分布 | 例如按小时柱状，看高峰在何时 |
| M-4 | 与内容解耦 | 指标只统计数量与时间，**不因记指标而重复存一份拼音原文** |

说明：用户明确要求——不能因为改走「读真实文字」就丢掉速度与频率；两者都要。

### 4.3 采集与运行（P0）

| ID | 需求 | 说明 |
|----|------|------|
| R-1 | 本地启动采集 | 命令行即可开始 / 停止（Ctrl-C 落库） |
| R-2 | 可选 verbose | 实时打印落库片段，便于验证是否在工作 |
| R-3 | 权限可降级 | 某一权限未授权时，对应能力关闭并提示，另一路尽量继续 |
| R-4 | （后续）后台常驻 | 不必长期开着终端；可用 launchd 等（已讨论，未做） |

### 4.4 隐私与安全（P0 原则 / P1 落地）

| ID | 需求 | 说明 |
|----|------|------|
| P-1 | 纯本地存储 | 默认 SQLite（如 `~/.keytrack/keytrack.db`），不联网上传 |
| P-2 | 敏感信息过滤 | 密码框、支付类字段等尽量不记或过滤（原则已达成共识，过滤逻辑未完整实现） |
| P-3 | 数据仅自用 | 产品定位明确排除「装到别人电脑」类用途 |

### 4.5 体验增强（P1 / P2）

| ID | 需求 | 优先级 |
|----|------|--------|
| U-1 | 本地网页看板（时间线 + 频率热力图） | P1 |
| U-2 | 窗口 / 网页标题（精确到文件或标签） | P2 |
| U-3 | 语言标签（拼音 / 英文 / 中文等） | P2（若内容已是上屏汉字，优先级下降） |
| U-4 | 中文速度用「上屏字数/分钟」 | P1 |
| U-5 | 对读不到的应用自动兜底策略 | P1（见第 6 节） |

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 平台 | 优先 macOS（当前开发与试用环境） |
| 技术栈（已选） | Python；本地 SQLite；MVP 回看为终端 CLI；网页看板可选后续 |
| 性能 | 采集常驻时对打字延迟感知应可忽略；大文档场景避免卡顿（已有长度上限等防护思路） |
| 可观测 | 权限缺失、某 app 读不到时，应有明确提示或探测手段（已有 `probe` 方向） |
| 合规 / 系统 | 遵守 macOS 隐私授权模型（辅助功能、输入监控等），不绕过系统限制 |

## 6. 技术路线与决策记录

### 6.1 已尝试 / 已实现

| 方案 | 作用 | 结论 |
|------|------|------|
| 物理按键监听（pynput） | 频率、节奏；文本重建 | 英文可用；**中文只能到拼音**；可覆盖几乎所有 app 的「键」 |
| 前台应用名（NSWorkspace） | 应用归属 | 可用 |
| 辅助功能读聚焦控件 AXValue | 真实上屏文字 | **原生控件有效**；**Cursor 等 Electron 常读不到**，试跑中内容路为空 |
| 内容 + 指标双路并行 | 同时满足 C 与 M | 架构已定：内容一路、指标一路，权限独立 |
| `probe` 探测 | 验证哪类 app 可读 | 用于诊断覆盖空白 |

### 6.2 关键矛盾（需求推动的选型）

1. **要真实中文** → 不能只靠物理按键重建。  
2. **要全应用覆盖（含 Cursor）** → 纯辅助功能不够。  
3. **要频率 / 速度** → 必须保留物理按键（或等价）指标路。  

因此：**内容采集与操作指标必须拆开**；内容路需要能覆盖 Electron 的方案。

### 6.3 已采用方向（2026-07-28 落地，v2 架构）

**采集收敛进输入法（RIME / 鼠须管 + librime-lua），零权限、随输入法常驻。**

- 内容：`rime/keytrack_logger.lua` 经 `commit_notifier` 取上屏文字 → jsonl
- 指标：同一 lua 里把按键按分钟聚合成 `{分钟, 各键次数}` → 另一个 jsonl
  （不存按键时间线，守住 M-4）；pynput 降级为可选（`--pynput`）
- 入库：`keytrack/ime_ingest.py` 吸入 SQLite；launchd 常驻 helper（install-agent）
  负责应用归属采样与及时入库；查询前自动补录兜底
- 应用归属：CGWindowList 直查窗口服务器（NSWorkspace 在无 runloop 的常驻进程
  返回过期值——锁屏后停在 loginwindow，实测踩坑后更换）
- 挂载与部署机制参考 rime-typing-speed

理由：

- 输入法处于几乎所有应用的文本输入上游，与目标是否为 Electron 无关  
- 开源可挂 Lua 钩子；已有仅统计速度、不记内容的参考（如 rime-typing-speed），可改为记内容并写入本项目库  

代价与边界（需求方需接受）：

- 日常输入法需切换为 RIME（可用雾凇拼音等降低成本）  
- 仅 RIME 激活时内容路完整；切回系统拼音则内容中断  
- 粘贴、非输入法路径的文字可能漏记（可用辅助功能作可选补充）  
- 英文直通模式需单独处理，否则可能漏记  

并行保留：

- **输入监控**：频率、速度、节奏（M-1～M-3）  
- **辅助功能（可选）**：粘贴与非 RIME 场景的补充  

### 6.4 曾评估但未作为主路径

| 方案 | 未主推原因 |
|------|------------|
| 仅用 keylogger 类开源项目 | 伦理与产品形态不符；可参考文本重建，不可整包照搬 |
| 拼音猜汉字 | 同音字多，不可靠 |
| 自研完整 IMK 输入法 | 工程量大；优先挂 RIME Lua |

## 8. 命令与产物（实现现状摘要）

便于对照需求，不替代用户手册：

| 能力 | 命令 / 位置 |
|------|-------------|
| 一次性配置输入法钩子 | `kbd.py setup-ime` |
| 常驻采集（登录自启） | `kbd.py install-agent` / `uninstall-agent` / `status` |
| 前台手动采集 | `kbd.py record [-v] [--pynput]` |
| 今日回看 | `kbd.py today [--full] [--json]` |
| 指定日 | `kbd.py show <day> [--json]`；有数据的日期 `kbd.py days` |
| 手动补录 | `kbd.py ingest` |
| 查询接口 | `keytrack/query.py`；schema 见 docs/SCHEMA.md |
| 探测 AX 可读性 | `kbd.py probe` |
| 数据默认路径 | `~/.keytrack/keytrack.db`（事件暂存 `~/.keytrack/ime_{commits,keys}.jsonl`） |

## 9. 开放问题

1. **输入法路线确认**：是否接受以 RIME 为日常输入法，换取全应用中文内容？  
2. **英文与粘贴**：漏记是否可接受，还是必须辅助功能双写？  
3. **敏感过滤规则**：密码框之外，是否按应用黑名单（如银行 App）整段不记？  
4. **回看形态优先级**：先巩固终端，还是尽快做网页看板？  
5. **历史拼音数据**：旧库中按键模式产生的拼音片段是否清理 / 归档？

## 10. 对话决策时间线（摘要）

| 顺序 | 用户意图 / 决策 |
|------|-----------------|
| 1 | 不满「只统计按键」；要「今天输入了什么」；先调研 GitHub 再动手 |
| 2 | 技术栈选 Python；MVP 先采集 + 本地存储 + 终端回看 |
| 3 | 需要识别输入所在应用 |
| 4 | 试跑后发现中文变拼音；要求语言/内容正确 → 选辅助功能读上屏文字 |
| 5 | 担心丢掉速度、频率 → 要求内容与指标并存 |
| 6 | 切换辅助功能后 Cursor 等场景采不到；权限已给 |
| 7 | **要求全应用可读**；提出「开源输入法取数」→ 评估为可行主路径 |
| 8 | 将以上整理为本文档 |
| 9 | 输入法内容路落地（鼠须管+雾凇拼音+lua 钩子）；修复 NSWorkspace 归属过期问题（换 CGWindowList） |
| 10 | **用户决策：采集全部收敛进输入法**（lua 记上屏文字 + 按键分钟桶，零权限）；launchd 常驻入库；留 JSON/Python/SQLite 三层查询接口供看板与 Swift 状态栏 |
